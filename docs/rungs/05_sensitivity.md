# Rung 05 - sensitivity study and mixed precision

Status: not started (milestone M4). This is the project's own finding.

## Question

Quantizing everything costs some quality. Is the damage spread evenly, or do a
few parts of the network cause most of it?

## Method

1. Define layer groups. A reasonable first cut: per transformer block, split into
   attention projections and MLP, plus the embedding and the output head.
2. For each group, build a model where **only that group** is int8 and the rest
   is float32. Measure `mean_kl` and `top1_agreement` against rung 01 on a fixed
   subset of the calibration data (WikiText-2 train, not test).
3. Rank groups by damage per byte saved.
4. Build `05_ort_int8_mixed`: quantize everything except the top-k most damaging
   groups. Sweep k to trace a curve of size against quality.
5. Evaluate the chosen point on the test split like any other rung.

The reverse experiment (everything int8 except one group) is a useful
cross-check: the two rankings should broadly agree. If they do not, the groups
interact, which is worth a sentence in the write-up.

## Deliverables

- A bar chart: quality loss per layer group.
- A curve: model size against KL for k = 0 … all.
- One mixed rung in the main table.
- Two or three sentences interpreting the pattern (for example, whether early
  or late blocks, attention or MLP, are the fragile ones) - stated only as far
  as the data supports.

## Implementation notes

ONNX Runtime's quantizer accepts a list of nodes to exclude; mapping layer
groups to node names in the exported graph is the main piece of work. Check the
current documentation for the exact option.

## Acceptance

The mixed rung sits between rung 02 and the full int8 rung on both size and
quality, and the charts are generated by a script from committed results.
